СПИСОК ТРЕБУЮЩИХСЯ ИСПРАВЛЕНИЙ
Проект: Crypto Wallet (дипломный проект, реальных пользователей нет)
Дата аудита: 04.10.2026

Приоритеты учитывают, что приложение демонстрационное: работает на тестовой сети
Sepolia, на защите показывается сценарий из PROJECT_CONTEXT.md (раздел 19).
Поэтому в первую очередь исправляется то, что может сломать демонстрацию или
вызвать вопросы комиссии по безопасности и качеству кода. Промышленное усиление
(hardening) вынесено в отдельный раздел и либо не делается, либо описывается в
пояснительной записке как известное ограничение.


======================================================================
1. ОБЯЗАТЕЛЬНО ИСПРАВИТЬ (корректность и главная тема диплома - безопасность)
======================================================================

1.1. Тяжёлая криптография блокирует интерфейс
  Файлы: lib/core/security/pin_hasher.dart, lib/core/security/hd_wallet.dart,
         lib/features/authentication/data/datasources/auth_local_datasource.dart,
         lib/features/wallet/data/datasources/wallet_local_datasource.dart
  Проблема: хеш PIN (20000 раундов HMAC) занимает ~0.3 с на ПК, деривация ключа
            из мнемоники 0.3-0.9 с. На телефоне в несколько раз дольше. Всё
            выполняется в UI-изоляте при каждом вводе PIN, отправке транзакции,
            создании и восстановлении кошелька - интерфейс замирает.
  Решение: вынести PinHasher.hash/verify и HdWallet.derivePrivateKey/addressOf в
           Isolate.run(...). Показывать индикатор загрузки.

1.2. Нет таймаутов на RPC-запросы
  Файл: lib/features/wallet/data/datasources/blockchain_datasource.dart
  Проблема: Web3Client работает с http.Client без таймаута. При плохой сети
            операции (баланс, оценка газа, отправка) зависают бесконечно.
  Решение: обернуть вызовы в .timeout(Duration(seconds: 15)) либо передать
           клиент с таймаутом. TimeoutException уже обрабатывается в Failure.from.

1.3. Падение всего списка активов из-за одного токена
  Файл: lib/features/assets/data/repositories/assets_repository_impl.dart
  Проблема: Future.wait в getAssets - ошибка balanceOf одного токена убирает и
            баланс основной монеты.
  Решение: запрашивать токены отдельно с try/catch (при ошибке баланс токена = 0
           или помечается как недоступный), баланс нативной монеты возвращать всегда.

1.4. Кеш активов портится методом getNativeAsset
  Файл: lib/features/assets/data/repositories/assets_repository_impl.dart
  Проблема: getNativeAsset перезаписывает запись кеша только полем balance, и
            балансы токенов обнуляются при следующем чтении кеша.
  Решение: при записи сохранять существующие данные о токенах (merge) либо не
           писать кеш в этом методе.

1.5. Разбор ответа эксплорера вне try/catch
  Файл: lib/features/transactions/data/repositories/transaction_repository_impl.dart
        lib/features/transactions/data/datasources/transaction_remote_datasource.dart
  Проблема: ошибки разбора JSON (TypeError, FormatException) не являются Failure,
            поэтому блок "on Failure" не срабатывает, и откат на кеш не выполняется.
            В remote_datasource используется ленивый result.cast<>().
  Решение: в getTransactions ловить любые исключения и приводить через Failure.from;
           в fetch использовать явное преобразование списка внутри try.

1.6. Failure.from скрывает реальные ошибки и показывает сырые тексты
  Файл: lib/core/errors/failures.dart
  Проблема: любое неизвестное исключение (в том числе баги кода) превращается в
            "Network error"; для RPCError показывается сырое сообщение узла.
  Решение: неизвестные ошибки - отдельный UnknownFailure с общим текстом
           (подробности только в debug-логе без секретов); для RPCError
           мапить известные случаи, остальные показывать общим сообщением.

1.7. Неверное отображение истории транзакций
  Файл: lib/features/transactions/data/models/transaction_model.dart
  Проблемы:
   - вызовы контрактов (ERC-20) показываются как отправка 0 ETH;
   - у входящих транзакций показывается комиссия отправителя;
   - для pending-транзакций timeStamp=0 даёт дату 1970 года;
   - только 50 последних записей, без пагинации.
  Решение: для входящих не показывать комиссию (или подписывать "комиссия оплачена
           отправителем"); при timeStamp=0 подставлять текущее время / "ожидает";
           записи с value=0 и непустым input помечать как "вызов контракта".

1.8. Гонка при смене сети (устаревшие ответы перезаписывают данные)
  Файлы: lib/features/transactions/presentation/providers/transactions_provider.dart,
         lib/features/assets/presentation/providers/assets_provider.dart
  Проблема: refresh() не проверяет, что сеть/адрес не изменились за время запроса.
            Ответ сети A может заменить данные сети B.
  Решение: запомнить chainId и address перед запросом и сравнить после await.

1.9. Опрос pending-транзакций никогда не останавливается
  Файл: lib/features/transactions/presentation/providers/transactions_provider.dart
  Проблема: если транзакция отброшена из mempool, опрос идёт каждые 5 с вечно,
            в том числе при заблокированном приложении.
  Решение: ограничить число попыток/время (например, 30 минут), увеличивать
           интервал (backoff), пометить транзакцию как "не найдена/отброшена".

1.10. Незавершённое создание кошелька
  Файлы: lib/features/onboarding/presentation/providers/onboarding_provider.dart,
         lib/features/authentication/presentation/providers/auth_provider.dart
  Проблема: сид сохраняется до установки PIN. Если приложение завершится между
            этими шагами, сид останется в хранилище, а SessionNotifier определит
            состояние как "нет кошелька"; следующее создание перезапишет сид.
  Решение: при старте, если есть мнемоника без PIN (или PIN без кошелька),
           очищать хранилище; либо сначала устанавливать PIN, затем сохранять сид.

1.11. Форма PIN после ошибки
  Файл: lib/features/onboarding/presentation/widgets/pin_setup.dart
  Проблема: после ошибки сохранения остаётся шаг "Repeat PIN" с уже введённым
            первым PIN.
  Решение: сбрасывать _first, когда приходит widget.error.

1.12. Статус транзакции в кеше расходится между локальным и удалённым
  Файл: lib/features/transactions/data/repositories/transaction_repository_impl.dart
  Проблема: trackTransaction обновляет только локальный кеш (sent:), а при слиянии
            побеждают данные эксплорера (txs:), где статус может быть устаревшим.
  Решение: в _merge при равных хешах брать более "поздний" статус
           (confirmed/failed приоритетнее pending).

1.13. Мелкие ошибки интерфейса
  - lib/features/assets/presentation/pages/asset_details_page.dart: цена выводится
    с символом "$" независимо от выбранной валюты - использовать Formatters.fiat.
  - lib/features/onboarding/presentation/pages/create_wallet_page.dart: очистка
    буфера обмена через 30 с стирает любые скопированные позже данные. Очищать,
    только если в буфере всё ещё мнемоника.
  - lib/main.dart: нет обработки ошибок инициализации (повреждённый Hive-бокс
    даёт белый экран). Обернуть в try/catch, при ошибке кеша - удалить бокс.

1.14. Блокировка при забытом PIN (минимально для демонстрации)
  Файлы: lib/features/authentication/presentation/pages/pin_page.dart
  Проблема: на экране ввода PIN нет способа сбросить кошелёк. На iOS данные
            Keychain сохраняются даже после удаления приложения, и при забытом PIN
            кошелёк недоступен навсегда (в том числе на демонстрационном
            устройстве).
  Решение: добавить кнопку "Забыли PIN? Сбросить кошелёк" с предупреждением
           (кошелёк удаляется, восстановление по сид-фразе). Это безопасно, так
           как без сида средства всё равно недоступны.


======================================================================
2. БЭКЕНД (нужно исправить, чтобы не было вопросов на защите)
======================================================================

2.1. Секрет JWT по умолчанию
  Файл: backend/app/config.py
  Проблема: jwt_secret = "change-me" по умолчанию, проверки при старте нет.
  Решение: если JWT_SECRET не задан или равен "change-me" - завершать запуск с
           ошибкой (кроме режима тестов).

2.2. Эндпоинт истории транзакций без авторизации
  Файлы: backend/app/routers.py, backend/app/services.py
  Проблема: открытый прокси, тратящий ключ Etherscan; каждый запрос пишет в БД.
  Решение: для диплома достаточно задокументировать, что это публичные данные
           блокчейна, и оставить ограничение запросов; либо добавить авторизацию
           (Depends(current_user)), если это не ломает клиент.

2.3. Ограничение запросов (rate limit)
  Файлы: backend/app/main.py, backend/app/cache.py
  Проблемы:
   - доверие заголовку X-Forwarded-For при прямом доступе к API;
   - при ошибке Redis incr_with_ttl возвращает 0 (лимит отключается);
   - нет отдельного ограничения для /auth/login.
  Решение: использовать X-Forwarded-For только если запрос пришёл от nginx
           (параметр trusted proxy); при ошибке Redis использовать резервный
           счётчик в памяти; для /auth/* задать более строгий лимит.

2.4. Фильтр reject_secrets
  Файл: backend/app/main.py
  Проблема: простая проверка подстрок легко обходится (экранирование \u, вложенные
            ключи). Это не защита, а подстраховка.
  Решение: проверять распарсенный JSON рекурсивно по именам ключей; в
           документации честно описать как "дополнительную защиту", основная
           гарантия - клиент никогда не отправляет секреты, и у API нет полей
           для них.

2.5. Проблемы целостности и ошибок БД
  Файлы: backend/app/routers.py, backend/app/database.py, backend/app/services.py
  - регистрация, device token, настройки: гонка check-then-insert приводит к
    ошибке 500 (ловить IntegrityError и возвращать 409);
  - добавить уникальный индекс (chain_id, address, tx_hash) в transactions_cache;
  - при отдаче из резервного кеша (_stored) статусы транзакций устаревают -
    обновлять запись при повторной загрузке или не использовать БД как кеш
    статусов;
  - валидировать network (список из NETWORKS) и currency (список поддерживаемых).

2.6. Клиент HTTP на каждый запрос
  Файл: backend/app/services.py (get_http)
  Проблема: новый httpx.Client на каждый запрос, нет пула соединений.
  Решение: один клиент на приложение (lifespan) либо dependency с общим клиентом.

2.7. Защита от перебора аккаунтов
  Файл: backend/app/routers.py, backend/app/security.py
  - для несуществующего пользователя выполнять фиктивный hash (одинаковое время);
  - не раскрывать наличие email в ответе регистрации (по желанию).

2.8. Тесты бэкенда
  Добавить тесты на: отсутствие JWT_SECRET, отказ при запросе с полем seed/mnemonic,
  лимит запросов, IntegrityError при повторной регистрации.

3. ЖЕЛАТЕЛЬНО (улучшает оценку, не критично)
======================================================================

3.1. Привязка проверки к use case, а не только к UI
  Сейчас confirmAuth вызывается только в UI (send_page.dart, settings_page.dart).
  Для архитектурной чистоты: добавить параметр/объект "AuthorizationToken" в
  SendTransaction и ExportWallet либо проверку в уровне домена.

3.2. Шифрование сида с использованием PIN
  Сейчас сид лежит в Keystore/Keychain открытым текстом, PIN - только
  интерфейсный барьер. Вариант: шифровать мнемонику ключом, производным от PIN
  (AES-GCM + PBKDF2/Argon2). В PROJECT_CONTEXT.md сказано "encrypt sensitive
  data", поэтому либо реализовать, либо описать в записке как принятое решение
  (опора на аппаратное хранилище ОС).

3.3. Биометрия привязана только к флагу
  Для полноценной привязки хранить ключ шифрования с требованием биометрии
  (Android Keystore setUserAuthenticationRequired). Либо описать как ограничение.

3.4. PIN
  - отсекать тривиальные PIN (000000, 123456, одинаковые цифры);
  - блокировка должна нарастать (30 с, 2 мин, 10 мин...);
  - использовать монотонное время вместо DateTime.now() (перевод часов).

3.5. Отправка транзакции
  - использовать EIP-1559 (maxFeePerGas/maxPriorityFeePerGas) вместо legacy gasPrice;
  - добавить запас к gasLimit (10-20%) для адресов-контрактов;
  - предупреждать при отправке на свой адрес, нулевой адрес или адрес контракта
    (eth_getCode);
  - пересчитывать комиссию непосредственно перед подписанием;
  - кнопка "Максимум" с учётом комиссии.

3.6. Защита экрана на iOS
  Скрывать содержимое в переключателе приложений (оверлей при inactive) - на
  Android FLAG_SECURE уже есть.

3.7. Сид-фраза в диалоге настроек
  - заменить SelectableText на обычный Text (без копирования);
  - убедиться, что диалог закрывается при автоблокировке (проверить вручную:
    открыть сид, свернуть приложение на 60+ секунд, вернуться).

3.8. Обновление зависимостей
  hive 2.2.3 / hive_flutter 1.1.0 не поддерживаются - заменить на hive_ce или
  оставить с пометкой в записке. web3dart 2.7.3 -> 3.0.3 (проверить совместимость).
  bip32/bip39 старые, но стабильные - оставить с упоминанием.

3.9. Тесты Flutter
  Добавить тесты на: параллельный рефреш при смене сети, getAssets при ошибке
  токена, Failure.from для неизвестных исключений, отброшенные pending-транзакции,
  PIN-блокировку и её сброс.

======================================================================
5. МОЖНО НЕ ИСПРАВЛЯТЬ (описать в записке как ограничения)
======================================================================

 - Отсутствие поддержки отправки ERC-20 токенов (по плану после MVP).
 - Только один аккаунт (индекс 0 пути BIP-44).
 - Историю берёт только Etherscan/бэкенд (50 записей).
 - Не шифруется Hive-кеш (содержит адрес и публичную историю, не секреты).
 - Адрес кошелька виден бэкенду при запросе истории (приватность метаданных).
 - Подпись release-сборки отладочным ключом.
 - PBKDF2 200k вместо 600k (OWASP) на бэкенде, 20000 раундов для PIN.
 - Миграции БД (Alembic) вместо create_all.
 - Полноценное управление токенами JWT (refresh, отзыв).
